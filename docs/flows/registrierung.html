Registrierungs-Flow

Verarbeitet neue Event-Anmeldungen, prüft Kapazität und erstellt Kalendereinträge.

Trigger: SharePoint - When an item is created
Liste: Anmeldungen

    SEND_WAIT --> UPDATE_STATUS

    UPDATE_STATUS --> END([Flow Ende])

Trigger

When an item is created

Der Flow wird ausgelöst, wenn ein neuer Eintrag in der SharePoint-Liste Anmeldungen erstellt wird. Diese Liste dient als temporäre Warteschlange für die Verarbeitung.

Aktionen

Schritt Aktion Typ Beschreibung
1 Get Event Details SharePoint - Get item Lädt Event-Stammdaten basierend auf Event-ID
2 Get User Profile Office365Users Lädt Profildaten des anmeldenden Users
3 Count Registrations SharePoint - Get items Zählt aktuelle Anmeldungen für das Event
4 Check Capacity Condition Prüft ob Kapazität erreicht
5a Create Registration SharePoint - Create item Erstellt Eintrag in Event visitors
5b Create Waitlist Entry SharePoint - Create item Erstellt Wartelisten-Eintrag
6 Convert Timezone Expression Konvertiert Zeiten nach Europe/Berlin
7 Create Calendar Event Outlook - Create event Erstellt Kalendereintrag beim User
8 Send Email Outlook - Send email Sendet Bestätigungs-/Wartelisten-Mail
9 Update Status SharePoint - Update item Markiert Anmeldung als verarbeitet

Expressions

Expression Verwendung Erklärung
triggerOutputs()?['body/Event registered/Id'] Get Event Details Extrahiert Event-ID aus dem Lookup-Feld der Anmeldung
length(body('Get_Registrations')?['value']) Capacity Check Zählt die Anzahl der vorhandenen Registrierungen
greater(variables('currentCount'), body('Get_Event')?['Capacity']) Condition Prüft ob aktuelle Anzahl größer als Kapazität
convertTimeZone(body('Get_Event')?['StartDate'],'UTC','W. Europe Standard Time') Calendar Event Konvertiert UTC-Startdatum nach deutscher Zeitzone
formatDateTime(variables('localStart'),'dd.MM.yyyy HH:mm') Email Body Formatiert Datum für E-Mail-Anzeige

Fehlerbehandlung

flowchart TD
    TRY[Try Scope] --> |"Erfolg"| SUCCESS[Status: Completed]
    TRY --> |"Fehler"| CATCH[Catch Scope]
    CATCH --> LOG[Log Error to SharePoint]
    LOG --> STATUS_ERR[Status: Failed]
    STATUS_ERR --> NOTIFY[Notify Admin]

Der Flow verwendet ein Try-Catch-Pattern mit Scopes:

  • Try Scope: Enthält alle Hauptaktionen
  • Catch Scope: runAfter: { "Try_Scope": ["Failed", "TimedOut"] }
  • Bei Fehler wird der Status in der Anmeldungen-Liste auf "Failed" gesetzt

Hinweise

Assistenz-Modus

Wenn varAssistancetrue gesetzt ist, wird die Anmeldung für eine andere Person durchgeführt. Der Flow prüft dann das Feld RegisteredFor statt des aktuellen Users.

Duplikat-Prüfung

Vor der Registrierung wird geprüft, ob der User bereits für das Event registriert ist oder sich gerade in Bearbeitung befindet.
