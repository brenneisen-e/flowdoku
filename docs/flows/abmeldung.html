Abmelde-Flow

Verarbeitet Abmeldungen von Events mit Deadline-Prüfung und Wartelisten-Triggering.

Trigger: HTTP Request / Power App
Deadline-Prüfung: Aktiv

Flowchart

flowchart TD
    START([Trigger: HTTP Request]) --> PARSE[Parse Request Body]
    PARSE --> GET_REG[Get Registration Details]
    GET_REG --> GET_EVENT[Get Event Details]
    GET_EVENT --> CHECK_DEADLINE{Deadline
überschritten?}

    CHECK_DEADLINE --> |"Vor Deadline"| DELETE_REG[Delete Registration]
    CHECK_DEADLINE --> |"Nach Deadline"| LATE_UNREG[Late Unregistration
Handling]

    DELETE_REG --> DELETE_CAL[Delete Calendar Event]
    DELETE_CAL --> TRIGGER_WAIT[Trigger Waitlist Flow]
    TRIGGER_WAIT --> SEND_CONFIRM[Send Unregister
Confirmation]

    LATE_UNREG --> MARK_NOSHOW[Mark as No-Show]
    MARK_NOSHOW --> SEND_LATE[Send Late Cancel Info]

    SEND_CONFIRM --> RESPOND[HTTP Response: Success]
    SEND_LATE --> RESPOND

    RESPOND --> END([Flow Ende])

Trigger

HTTP Request / Power App Trigger

Der Flow wird von der Power App aufgerufen, wenn ein User sich von einem Event abmeldet. Die Registrierungs-ID wird als Parameter übergeben.

Request Schema

{
  "type": "object",
  "properties": {
    "registrationId": { "type": "integer" },
    "eventId": { "type": "integer" },
    "userId": { "type": "string" }
  },
  "required": ["registrationId", "eventId"]
}

Aktionen

Schritt Aktion Typ Beschreibung
1 Parse Request Parse JSON Parst den Request Body
2 Get Registration SharePoint - Get item Lädt Registrierungsdetails
3 Get Event SharePoint - Get item Lädt Event-Stammdaten inkl. Deadline
4 Check Deadline Condition Prüft ob aktuelle Zeit vor oder nach Deadline
5a Delete Registration SharePoint - Delete item Löscht Registrierung (vor Deadline)
5b Mark No-Show SharePoint - Update item Markiert als Absage nach Deadline
6 Delete Calendar Outlook - Delete event Entfernt Kalendereintrag
7 Trigger Waitlist Child Flow Startet Wartelisten-Flow
8 Send Confirmation Outlook - Send email Bestätigt Abmeldung per E-Mail

Deadline-Logik

flowchart LR
    NOW[Aktuelles Datum] --> COMPARE{Vergleich}
    DEADLINE[Event Deadline] --> COMPARE
    COMPARE --> |"NOW < DEADLINE"| BEFORE[Vor Deadline
Normale Abmeldung]
    COMPARE --> |"NOW >= DEADLINE"| AFTER[Nach Deadline
Späte Absage]

Vor Deadline

  • Registrierung wird komplett gelöscht
  • Kalendereintrag wird entfernt
  • Wartelisten-Flow wird getriggert
  • Bestätigungsmail wird gesendet

Nach Deadline

  • Registrierung wird als "No-Show" markiert
  • Kalendereintrag wird entfernt
  • Kein Wartelisten-Nachrücken (zu spät)
  • Info-Mail über späte Absage

Expressions

Expression Verwendung Erklärung
triggerBody()?['registrationId'] Get Registration Extrahiert Registrierungs-ID aus Request
convertTimeZone(utcNow(),'UTC','W. Europe Standard Time') Deadline Check Aktuelle Zeit in deutscher Zeitzone
less(variables('currentTime'), body('Get_Event')?['Deadline']) Condition Prüft ob aktuelle Zeit vor Deadline liegt
body('Get_Registration')?['CalendarEventId'] Delete Calendar ID des zu löschenden Kalendereintrags

Fehlerbehandlung

flowchart TD
    TRY[Try Scope] --> |"Erfolg"| RESP_OK[Response: 200 OK]
    TRY --> |"Fehler"| CATCH[Catch Scope]
    CATCH --> LOG[Log Error]
    LOG --> RESP_ERR[Response: 500 Error]

HTTP Response Codes:

  • 200 - Abmeldung erfolgreich
  • 400 - Ungültige Request-Parameter
  • 404 - Registrierung nicht gefunden
  • 500 - Interner Fehler
