E-Mail & Kalender Flow

Zentraler Flow für den Versand von Bestätigungsmails und die Erstellung von Kalendereinträgen.

Trigger: Child Flow
Connector: Office 365 Outlook

Flowchart

flowchart TD
    START([Trigger: Child Flow]) --> PARSE[Parse Input Parameters]
    PARSE --> SWITCH{Action Type}

    SWITCH --> |"registration"| REG_FLOW[Registration Flow]
    SWITCH --> |"unregistration"| UNREG_FLOW[Unregistration Flow]
    SWITCH --> |"waitlist"| WAIT_FLOW[Waitlist Flow]
    SWITCH --> |"promotion"| PROMO_FLOW[Promotion Flow]

    subgraph REG_FLOW[Registration]
        REG1[Build Email Body] --> REG2[Create Calendar Event]
        REG2 --> REG3[Send Confirmation Email]
    end

    subgraph UNREG_FLOW[Unregistration]
        UNREG1[Delete Calendar Event] --> UNREG2[Send Cancellation Email]
    end

    subgraph WAIT_FLOW[Waitlist]
        WAIT1[Build Waitlist Email] --> WAIT2[Send Waitlist Email]
    end

    subgraph PROMO_FLOW[Promotion]
        PROMO1[Create Calendar Event] --> PROMO2[Send Promotion Email]
    end

    REG3 --> RETURN[Return Result]
    UNREG2 --> RETURN
    WAIT2 --> RETURN
    PROMO2 --> RETURN

    RETURN --> END([Flow Ende])

Trigger

Child Flow / Run a Child Flow

Dieser Flow wird von anderen Flows als Child Flow aufgerufen. Er zentralisiert alle E-Mail- und Kalender-Operationen.

Input Parameter

Parameter Typ Pflicht Beschreibung
actionType String Ja registration, unregistration, waitlist, promotion
recipientEmail String Ja E-Mail-Adresse des Empfängers
recipientName String Ja Name des Empfängers
eventName String Ja Name des Events
eventDate DateTime Ja Startdatum/-zeit des Events
eventEndDate DateTime Ja Enddatum/-zeit des Events
eventLocation String Nein Veranstaltungsort
calendarEventId String Nein ID für Kalender-Löschung
qrCodeUrl String Nein URL zum QR-Code für Check-In

Kalender-Integration

Create Event

Feld Wert
Subject [Event-Name]
Start @{triggerBody()?['eventDate']}
End @{triggerBody()?['eventEndDate']}
Location @{triggerBody()?['eventLocation']}
Time Zone W. Europe Standard Time
Show As Busy

Zeitzone

Alle Kalendereinträge werden in der Zeitzone W. Europe Standard Time (Europe/Berlin) erstellt, um Konsistenz mit den deutschen Standorten sicherzustellen.

Expressions

Expression Verwendung Erklärung
triggerBody()?['actionType'] Switch Bestimmt den auszuführenden Pfad
convertTimeZone(triggerBody()?['eventDate'],'UTC','W. Europe Standard Time','dd.MM.yyyy') Email Body Formatiert Datum für Anzeige
convertTimeZone(triggerBody()?['eventDate'],'UTC','W. Europe Standard Time','HH:mm') Email Body Formatiert Uhrzeit für Anzeige
outputs('Create_Calendar_Event')?['body/id'] Return ID des erstellten Kalendereintrags

Output

Parameter Typ Beschreibung
success Boolean True wenn alle Aktionen erfolgreich
calendarEventId String ID des erstellten Kalendereintrags (bei registration/promotion)
emailSent Boolean True wenn E-Mail gesendet

Fehlerbehandlung

flowchart TD
    ACTION[E-Mail/Kalender Aktion] --> CHECK{Erfolgreich?}
    CHECK --> |"Ja"| SUCCESS[Return Success]
    CHECK --> |"Nein"| RETRY[Retry Logic]
    RETRY --> |"Max 3 Versuche"| CHECK
    RETRY --> |"Fehlgeschlagen"| FAIL[Log Error + Return Failure]

Retry-Logik für transiente Fehler:

  • Maximal 3 Wiederholungsversuche
  • Exponentielles Backoff (1s, 2s, 4s)
  • Nur bei HTTP 429 (Rate Limit) oder 503 (Service Unavailable)
